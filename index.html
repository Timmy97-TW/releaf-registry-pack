The staged text, figures and open questions for 33 iGEM registry part pages, prepared on 19 October 2026 so that two people can fill those pages in by hand on 20 October — before the freeze at 23:00 Taiwan time on 21 October.

The queue is split in two — 59 steps for person A, 56 for person B — so nobody edits a registry page the other is already in. A further 48 bracketed values were resolved before staging, each against something that corroborates it; the 70 above are left visible in the text so nothing unverified is pasted by accident.

Start here

  • The console→ One card per part, the staged text behind a copy button, thumbnails of every figure, and tick boxes that remember where you stopped. Four tabs: Queue, Parts, Figures, Decisions.
  • The Word pack→ The same content as a single document with the figures embedded, for reading and review away from the browser. 3.6 MB.
  • What the pull found→ Coverage by part family, the five parts with nothing written, the four characterisation legends with no figure, and the 44 distinct bracket placeholders behind the 118 on the live pages.
  • Which image goes where→ Every wiki image matched to its registry slot, with the wiki caption set beside the registry text so the band sizes can be checked row by row.
  • One row per part→ Status, sequence length, which sections exist, word counts, figure and placeholder counts, editor and last-updated date.
  • How the text was prepared→ What is in each folder, the rule used for resolving a bracketed value, and the structural check against the original Markdown.

The rest of the repo

  • upload/ — the 18 figures as PNG, named for their part and slot. These are the files to upload (manifest).
  • thumbs/ — 420 px copies the console displays. Not for upload.
  • modelling/ — 43 modelling figures with legends already written, offered to the Design sections (legends).
  • raw/ — the untouched API response for each of the 33 parts. The source of truth for everything else here.
  • model.json — staged text, resolutions and open questions per section.
  • steps.json — the 115 steps in order, with the A/B assignment. additions.json holds the new drafts and the fixes.

Not done

  • The two collection documents. Until they exist, the shared cloning block still sits on every composite part, which the Registry Rules say should not be duplicated.
  • Four empty figure slots. One characterisation slot on BBa_26XVQ3FS, and three captions that want sequencing traces rather than gels.
  • Five parts with no documentation at all — BBa_26A4MT29, BBa_26OSLRE4, BBa_26V6CPEV, and the two drafts. Opening text for them is staged in the queue.
  • One band size disagreement. The wiki says 1,145 bp for Module 1 (BBa_26XZYM10); that part's registry text says 1,660 / 1,721 bp, and 1,145 bp turns up instead on BBa_26CXI09X.
